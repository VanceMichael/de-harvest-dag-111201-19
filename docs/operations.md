# 本地运行说明

先运行单元测试，再执行演示命令。`python3 -m collector graph` 从干净临时目录发起
采集并处理响应，不需要外部网络；加 `--network` 可改用真实回环 HTTP 来源。

## graph 演示如何对照请求

演示结束打印的 `requests` 表逐路径列出“真正发出的请求”、状态序列与条件请求次数：

- 反复失败的附件只重发该附件自身（`/shared` 多次 500），目录与详情不随链重跑；
- 详情/目录的 304 是带 `If-None-Match` 的条件再验证，304 不改变已冻结依赖；
- 已成功的附件（如 `/new`）在进程重启后不重发；
- 晚到的旧代次附件通过 `ingest_late_product` 入库，不产生任何新请求。

`first_run_node_states` 给出第一阶段结束时每个节点的状态与尝试次数，
`final_works` 给出对外就绪状态（区分缺可选项与核心资料不齐），
`journals` 是取消、替代、晚期产物等领域事件流水。

## 其他命令

常规导入失败时返回非零退出码，事务中的原文和记录会一起回滚，可保留源文件再次处理。
查询模式只读取当前数据库，不会补采或删除来源数据。需要长期保留证据时，请备份整个数据库。
本地响应服务支持状态码、响应头、文本或 base64 字节正文、`delay` 延迟与 `gate` 门闩；
未配置路径返回未找到。每条路径的脚本独立推进，最后一个响应会重复；
可借请求记录核对调用顺序。数据文件的路径均相对项目根目录，修改工作目录前请确认
输入和数据库参数。
